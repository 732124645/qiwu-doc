# 项目由来

这一页想聊聊我为什么做栖梧，希望谁能用上它，以及为什么选择开源。

## 为什么要做

第一个原因，是市面上没有一个我觉得好用的 Node 开源后台框架。我想在它上面直接写业务。“好用”对我来说，就是功能齐全、默认安全，有测试和详细文档，敢拿来做项目。

用户、角色、菜单、部门、字典、参数、日志、定时任务、消息、文件、代码生成，这些常用功能得齐。审批流要有树形和 BPMN 两种设计器，支持零代码审批；表单设计器、国际化、基于 OAuth2 的单点登录和移动端都得有。这些在 RuoYi、芋道这样的 Java 后台里早已是标配，在 Node 这边却很难找齐。

安全应该默认就有。访问超出允许数据范围的记录，一律返回 404，不透露记录是否存在。防越权授予，避免把自己没有的权限给别人；防重复提交，避免同一次操作重复执行。密钥要加密存储，上传文件要按内容识别类型。我希望这些保护、测试和详细文档都准备好，不用自己补，拿来就能放心用。

第二个原因，是做小项目时，Node 的成本反而比 Java 低。我主要看三笔账。

先是人力。前后端都用 TypeScript，一个人就能把两边做完。校验规则和类型共用一份，不用前后端各写一遍。

然后是服务器。Node 服务一般比 Java 服务占用更少内存，小项目一台便宜的服务器就够，起步的负担小一些。

最后是开发速度。启动快，改完马上生效，写业务时能更快看到结果。部署就是一个 Node 进程加 Nginx，交付小项目很直接。

## 给谁用

我希望想转全栈的前端开发者能用上它。会 Vue 和 TypeScript，就能接着写后端，把前后端都做起来，不用再学 Java。可以从[前端开发者入门](/backend/)开始。

学生和新手可以看[从零开始教程](/beginner/)。从 Java、RuoYi 转过来的开发者，可以先读[Java 开发者入门](/java/)，把熟悉的功能和概念对上。

对于全栈小团队、外包工作室和独立开发者，我希望大家能以栖梧为基础，用一个仓库交付整套后台，把时间花在项目自己的业务上。

## 为什么开源

我把栖梧开源，是想让更多人用上，一起改进。选择 MIT，是因为它是最宽松的开源协议之一，可以放心用在商业项目里。用的时候遇到问题或有想法，欢迎提出来。
