# 打卡考勤

::: warning v1.10.0 历史说明
原生考勤曾在 [v1.10.0](https://github.com/732124645/qiwu-vue-admin/tree/v1.10.0) 公开。v1.11.0 的公开组合不包含考勤源码、页面和种子；以下说明仅适用于原历史版本，不是当前安装步骤。旧标签和历史记录保持可查，真实设备定位与现场打卡的验收限制也仍然适用。当前公开办公范围见 [OA 办公](/features/oa)。
:::

员工在移动端 **打卡**入口签到、签退和查看本人记录。管理员在 OA 下配置考勤规则、办公地点及查询记录。原生考勤使用独立的 OA 功能能力，不依赖审批开关，也不需要钉钉账号或打卡机；登录、租户套餐与权限检查仍然执行。

## 首次设置

每个租户一份规则，初始为**启用、Asia/Shanghai、不定位、保留 180 天**。初始化不覆盖管理员修改、停用或删除，也不生成打卡记录。

- **时区**：使用 IANA 时区，服务端按它计算工作日。
- **不定位（none）**：不调用设备定位。
- **办公地点（site）**：管理员设置地点经纬度、允许半径和精度阈值；员工点击打卡时只取一次前台 WGS84 位置，服务端校验距离和精度。
- **保留天数**：30 至 730 天，按租户规则由定时任务清理历史记录。初始任务每日 04:15 执行；管理员的修改和停用不会被初始化覆盖。备份保留策略由部署方另外管理。

## 签到与签退

每天一组上班签到和下班签退。时间由服务端产生，客户端不能指定员工、历史日期、时刻或来源。签退要求同一工作日已有签到，且晚于签到。

跨午夜就是新工作日，前一天的签到不能用于新一天签退。没有跨夜班、多班次、排班、节假日、补卡和离线补传能力，不适用于需要这些规则的考勤结算。

定位授权被拒、定位不支持或超时、精度不足、地点停用、超出范围时明确拒绝打卡，不自动降为不定位。定位和请求期间按钮禁用。结果不确定时先查原请求结果、再刷新今天状态，使用者才能选择重试；系统不会自动再发一次打卡。

每个动作带本人随机请求标识，服务端持久防重。相同请求和参数返回原结果，标识换参数或同日同动作的另一请求返回冲突。跨工作日不会把旧请求自动改成新一天的打卡。

## 本人与部门查询

本人记录永远限定当前用户。管理查询另需权限和部门数据范围，超级管理员也受租户隔离。记录保留当时的用户、部门、工作日、时区与规则快照，员工调部门不会搬移历史数据。没有任意改时间、代打卡或删除原始记录的业务接口。

日汇总展示打卡和批准的请假、出差时间段：

- 本人当天没有活动也返回一行空汇总。
- 部门汇总按当天有活动的“用户 + 当时部门”列出，一人可能有多个部门快照行；总数**不是员工总人数或完整出勤花名册**。
- 没有记录不代表旷工；批准假勤不代表已经签到；不判断迟到、早退、工时或扣薪。
- 假勤关联只展示类型、状态和时间，不暴露请假事由、目的地、费用或附件；审批变化不会删除原始打卡。

## 定位隐私与边界

员工原始经纬度只用于本次校验，不写入考勤表，请求审计与 HTTP 日志也遮挡位置字段。考勤保存办公地点快照、距离、精度和校验结果，不保存完整轨迹；没有后台持续定位权限。

设备或软件可以伪造客户端位置。当前没有 Wi-Fi、蓝牙、硬件证明或设备级防作弊，普通定位范围校验不能作为可靠在场证明。

## 发布前验证

H5 只用于开发与自动测试。小程序需配置合法 API 域名、定位用途和所需授权；App 需配置前台定位权限与发布信息。

**H5 自动化、App 与小程序构建已通过；真实 App 和小程序定位授权、现场签到签退尚未验收。** 构建成功不证明手机已获得权限或位置可用。上线前分别验证授权、拒绝授权、精度不足、越界、签到签退、重复点击、断网查结果、账号切换和午夜边界。

钉钉打卡机同步是独立可选集成，目前未实现、未启用。助手不提供代打卡工具。

接口、清理任务与时间规则见仓库的[原生考勤说明](https://github.com/732124645/qiwu-vue-admin/blob/v1.10.0/docs/attendance.md)。
