# 安全基线

下面这些措施**默认开启**，每一项都有对应的测试或自动检查。完整的威胁防护清单和测试见仓库的[安全文档](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/security.md#威胁防护与测试入口)。

## 认证与会话

- **不使用 JWT**。访问令牌和刷新令牌都是随机字符串，Redis 中只保存它们的哈希值；
- 访问令牌默认 30 分钟，活跃时自动续期，但**不会超过绝对上限**（12 小时；勾选"保持登录"或在手机端登录时为 7 天。这两个上限是固定的，不能配置）；
- 刷新令牌存放在 `HttpOnly` + `SameSite=Strict` 的 cookie 中，每次使用后都会更换。旧令牌被重复使用时，会吊销整个会话链；
- 刷新接口和会写入这个 cookie 的密码登录、短信登录都核对请求来源（`Origin`）：来自别的网站或来源为 `null` 时返回 403，防止别的网站把它自己的账号登录进你的浏览器（登录 CSRF）。反向代理要把 `Host` 和协议原样转给服务端，或者把控制台的地址写进 `CORS_ORIGIN`，见[部署 · 反向代理](/guide/deploy#反向代理-nginx)；
- 管理员重置密码、停用或删除用户，以及用短信找回密码时，该用户的所有会话都会失效；本人修改密码时，其他会话全部失效，只保留当前这一个；强制下线只结束被强退的会话（用"强退该用户"时结束这个用户的全部会话）。被结束的会话的 WebSocket 连接也会立即断开；
- 本人修改密码、短信找回密码、管理员重置密码时，还会**解除这个账号的微信小程序绑定**。这样即使有人曾用泄露的密码绑定了自己的微信，改密后也登录不了了。强制下线不会解绑。

## 登录防护

- 限流：按 IP 和按用户名分别计数。按 IP 的计数存在 Redis 里，部署多个服务实例时共用同一份额度；Redis 暂时出错时请求直接失败（返回 500），不会放行（见[部署 · 多实例部署](/guide/deploy#多实例部署)）；
- 同一个"用户名 + IP"连续失败 5 次会锁定 10 分钟。只锁这一对组合，所以别人无法借此把管理员账号锁死；
- 同一个用户名在多个 IP 上累计失败过多后，强制要求验证码；
- 不存在的用户名同样会计数，响应内容和耗时都与存在的用户名一致，无法借此探测账号是否存在；登录名必须符合账号的保存格式（全角先转成半角），其他写法返回 400，不会落到另一个计数上而暴露账号是否存在；
- 同时发出的多个密码尝试先计数、再校验密码，所以最多只有锁定阈值那么多次能走到密码校验，见仓库的[安全文档](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/security.md#威胁防护与测试入口)；
- 支持 IP 黑名单（单个地址或 CIDR 网段，不支持 `*` 通配，写错的条目会被忽略）、首次登录强制改密、密码过期、密码复杂度策略（前后端使用同一套规则）。

## 微信小程序登录

功能介绍和启用步骤见[登录与账号 · 微信小程序登录](/features/login#微信小程序登录)。这里只列安全规则：

- **默认关闭**。开关 `auth.wx_mp.enabled` 没打开，或者缺少 `WX_MP_APPID` / `WX_MP_SECRET` 时，登录和绑定接口都返回 404；
- 小程序传来的 `code` 只能用一次；微信返回的 `session_key` 服务端收到后直接丢弃，既不保存，也不发给客户端；
- 还没绑定的微信账号会拿到一张**绑定票据**：5 分钟内有效，只能用一次，只能从同一个 IP 使用；
- 绑定时要用账号密码或短信验证码证明身份，验证码、失败锁定和限流规则和普通登录一样。同一个微信账号不能绑定两次（返回 409），一个账号也只能绑定一个微信；
- 解绑不受开关限制，并且会让本人在其他手机上的登录全部失效（当前这台保留）；
- 每次微信登录都记在登录日志里，类型是 `wx-mp`。身份验证通过但绑定被拒时，也会记一条失败的日志。

## 单点登录（OAuth2）

功能介绍见[单点登录（OAuth2）](/features/oauth)，接入细节见 [OAuth2 接入指南](/reference/oauth2)。这里只列安全规则：

授权码方式必须用 `S256` 的 PKCE，只支持带密钥的机密客户端；客户端密钥只显示一次，数据库只存 SHA-256 摘要；回调地址逐字比对，请求无效时同意页从不跳转。第三方令牌只能调用用户信息接口；用户改密、被停用或被强退，或客户端被停用时，相关会话一起失效；日志里的密钥、授权码和令牌自动脱敏。规则见仓库的 [OAuth2 文档](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/oauth2.md#7-令牌隔离与会话)。

## 越权访问（IDOR）

- 所有按 id 查询、修改、删除的接口，都会先检查这条记录是否在当前用户的数据范围内，超出范围返回 404；
- 防越权授予：不能给别人超过自己的权限，详见[权限与数据范围](/features/permission)。重置别人的密码、设置别人的登录手机号，要求能分配这个用户的全部角色；移动部门也按授予检查，见[防越权授予](/features/permission#防越权授予)；
- 流程表单的附件是私有文件：除了上传人、超级管理员和有文件列表"查看"权限（`storage.object.view`）的人，只有能查看这个流程实例、并且能看到这个附件字段的人才能下载，见[工作流 · 附件](/features/workflow#附件)。
- 审批数据按字段权限过滤：只有超级管理员和该流程的流程管理员能看到全部字段，其他人看不到在流程任一节点隐藏过的字段（页面、导出和筛选里都没有）。因为流程管理员能看全部字段，修改流程管理员名单需要单独的权限 `wf.model.managers`，只有 `wf.model.modify` 的人不能把自己加进去（返回 403），见[工作流 · 审批数据里的字段权限](/features/workflow#审批数据里的字段权限)。

## 租户隔离

开启[多租户](/features/multi-tenancy)后，ORM（把代码里的对象读写翻译成 SQL 的那一层）会给每张租户表的查询、写入和联表自动加上当前租户的条件，超级管理员也跳不过；手写的 SQL 由自动检查要求带上租户条件。访问别的租户的数据，和访问不存在的数据一样返回 404；租户里的人调用[平台专属页面](/features/permission#租户套餐与平台专属页面)的接口会被拒绝。会话属于哪个租户取自用户本身，没有可以切换租户的请求头。平台人员进入租户要有专门的权限，2 小时后自动退出，全程记入审计。测试入口见仓库的[安全文档](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/security.md#威胁防护与测试入口)。

## 注入与代码执行

- 只使用参数化 SQL，排序字段有白名单；有检查脚本禁止把字符串拼接进 SQL；
- 禁止 `eval`、`new Function` 和 `vm`（由 lint 和脚本检查）；
- 定时任务只能调用白名单中的处理函数，流程条件只能用结构化规则；
- 表单设计器保存的表单结构会在别人的浏览器里渲染，所以保存时前后端用**同一份白名单**检查：包含函数、会被当作代码执行的字符串（比如 `$FN:`）、事件和联动设置、未知组件时直接返回 400，白名单以外的设置被去掉，服务端只保存过滤后的结果，见[表单设计器 · 安全](/features/formkit#安全)；
- BPMN 只当作数据：只接受白名单元素，脚本、表达式、监听器、DOCTYPE 和超过 80 KiB 的文件一律拒绝，运行的是服务端从 XML 推出的树，见[工作流](/features/workflow)和仓库的 [BPMN 文档](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/workflow-bpmn.md#发布规则与错误)；
- `pnpm ci:local` 在构建之后扫描前端产物，确认里面没有白名单以外的 `eval` / `Function` 调用，也没有 wangeditor v4 的代码。

## XSS

- 富文本在保存时就经过白名单清洗（去掉 `style`、`on*`、`script` 和 `iframe`）；
- 站内信按纯文本处理；邮件预览在沙箱 iframe 中显示；
- 前端页面带严格的内容安全策略（CSP）。

## 文件上传

- 按**文件内容**识别真实类型，不相信扩展名；使用扩展名白名单，`html`、`svg`、`js` 永远不允许上传；
- 保存时使用随机文件名，防止路径穿越；
- 下载时强制 `attachment` + `nosniff` + `CSP sandbox`；
- 私有文件必须通过鉴权接口下载。

## SSRF

管理员可以配置的外部地址（S3、SMTP），服务端连接前会先解析 DNS，拒绝内网、本机和云厂商元数据服务的地址，只允许白名单中的端口。

修改 S3 存储配置时，只要改了**服务地址（Endpoint）**、**存储桶**或**访问密钥 ID** 中的任何一项，就必须重新填写**访问密钥**，否则返回 422，整次修改都不保存。这样，能修改存储配置的人没法把已经保存的密钥带到另一个地址去。

## 其他

- **Excel**：导出时，以 `=`、`+`、`-`、`@` 开头的单元格会被转义，防止公式注入；导入时限制文件大小和行数，拒绝包含宏的文件；解析前先统计每个部分解压后的真实大小，谎报大小的文件返回 400，不会耗尽内存，见[Excel 导入导出 · 导入限制](/core/excel#导入限制)；
- **重复提交**：新增类接口在服务端做了防重复提交，3 秒内的重复请求返回 429（写法见[防重复提交、限流与锁](/core/guards)）；
- **敏感数据**：密码使用 bcrypt 存储；第三方服务的密钥（比如 S3、SMTP）用 AES-256-GCM 加密后存入数据库；OAuth2 客户端密钥只存 SHA-256 摘要；日志中的密码、令牌等字段自动脱敏；
- **生产环境的密钥检查**：`APP_SECRET` 或 `SEED_ADMIN_PASSWORD` 含 `not-for-production` 标记时，生产环境的服务和数据库命令拒绝运行。仓库里提交的测试密码都带着这个标记，所以不会被误带到生产环境；它不判断强度，生产密钥要自己生成，见仓库的[安全文档](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/security.md#生产配置与凭据)；
- **智能助手**：[智能助手](/features/agent)按发起人本人的权限、数据范围和租户调用工具，写入从不在无人确认时执行，联网读取和外部 MCP 只连公网地址，模型等服务的密钥加密存库、只写不读，见仓库的[后台智能体（智能助手）](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/security.md#后台智能体智能助手)；
- **演示模式**：除登录、退出、进入和退出租户等少数操作外，写操作一律返回 403（超级管理员也一样），日志里的访客信息打码，见[部署 · 演示模式](/guide/deploy#演示模式)和仓库的[放行清单](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/security.md#演示模式的精确豁免)；
- **供应链**：锁定依赖版本；新版本发布满 24 小时才允许安装；依赖的安装脚本需要逐个审核；依赖许可证自动检查；
- **依赖许可与原创性检查**：`pnpm verify` 检查生产依赖的许可（只接受允许列表里的宽松许可，禁用包一律失败）、Web 用到的包必须登记为生产依赖、TypeScript、Vite、Vue、Element Plus 和 Vitest 在整个仓库只用一个版本，并拒绝其他后台项目的标识和冒号分隔的权限串；用模板开发的项目可以自行调整允许列表，见仓库的[依赖许可与原创性检查](https://github.com/732124645/qiwu-vue-admin/blob/main/docs/security.md#依赖许可与原创性检查)。

## 报告安全漏洞

**不要**在公开的问题、讨论或合并请求里写漏洞细节；请用 GitHub 私密漏洞报告提交：[源码仓库](https://github.com/732124645/qiwu-vue-admin) → **Security** → **Report a vulnerability**。支持版本、响应、披露和范围（包括不要对在线演示做破坏性测试）见[安全策略](https://github.com/732124645/qiwu-vue-admin/blob/main/SECURITY.md#报告漏洞)。
