# 国际化

内置简体中文（`zh-CN`）和英文（`en-US`）。国际化从第一行代码起就是必须遵守的规则：**`.ts` 和 `.vue` 文件里不能出现中文字面量**，所有面向用户的文字都通过翻译键输出。

## 覆盖范围

| 内容 | 做法 | 位置 |
| --- | --- | --- |
| 界面文字 | vue-i18n 翻译键 | `apps/web/src/locales/{zh-CN,en-US}/*.json` |
| 后端错误和提示 | 抛出错误时只带键和参数，返回前按请求语言翻译 | `apps/server/src/i18n/{zh-CN,en-US}/*.json` |
| 表单校验提示 | zod 错误映射为 `validation.*`，字段名为 `field.<域>.<属性>` | `packages/shared/src/i18n/` |
| 菜单名称 | 存翻译键（如 `menu.iam.users`）；管理员新建的菜单可以直接填写中英文 | 翻译文件 + 数据库 |
| 字典、参数 | `label_i18n` JSON 字段：`{"zh-CN": "男", "en-US": "Male"}` | 数据库 |
| 种子数据名称 | 角色、部门、岗位、流程名等存为翻译键（如 `seed.role.root`） | 共享包翻译文件 |
| 消息模板 | 同一个编码按语言各存一行，按收件人的语言发送 | 数据库 |
| Excel | 表头、字典值按请求语言输出，时间按请求时区输出 | — |
| 第三方组件 | Element Plus、dayjs、ECharts、富文本编辑器、Cron 编辑器、验证码、流程设计器等随语言一起切换 | — |

## 切换语言

前端调用 `setLocale('en-US')`，一次性完成以下操作：切换 vue-i18n 和 Element Plus 的语言、切换所有第三方组件的语言、修改 `<html lang>`、之后的请求带上 `Accept-Language` 头，并把用户的语言偏好保存到后端。

后端判断语言的顺序：`?lang=` 参数 → `Accept-Language` 头 → 用户保存的语言 → `zh-CN`。

## 后端抛出错误

```ts
throw new BizError(Err.IAM_USERNAME_TAKEN, { username })
```

每个错误码对应一个翻译键 `error.<域>.<名称>`，返回给前端的 `msg` 已经是翻译好的文字。

## 自动检查

`pnpm i18n:check`（`pnpm verify` 的一部分）会检查：

- 两种语言的翻译键是否完全一致；
- `.ts` 和 `.vue` 文件里是否有中文字面量。

新增翻译键时，必须同时在 zh-CN 和 en-US 中添加。

## 增加一种语言

1. 复制各处的 `en-US` 目录，改成新语言的代码（比如 `ja-JP`）并翻译；
2. 在前端语言列表中注册，给第三方组件加上对应的语言包；
3. 数据库中的 `*_i18n` 字段和消息模板，按需补上新语言的内容。
