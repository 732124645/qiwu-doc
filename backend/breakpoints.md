# 断点调试

**断点**是你在代码某一行做的标记。程序运行到这一行时会**暂停**，这时你可以看到每个变量当前的值，再一步一步往下执行，看程序到底走了哪条路。这种找问题的方法叫**断点调试**。

它和[排查问题](/backend/debugging)里讲的方法不一样：

| 方法 | 适合什么 |
| --- | --- |
| 看日志、按 traceId 搜索 | 事后回看：请求已经结束了，看它留下的记录 |
| 断点调试 | 现场观察：让程序停在某一行，直接看变量的值 |

两种方法经常一起用：先用 traceId 和日志确定问题大概在哪里，再到那里打断点细看。

## 前端（电脑端）

### 准备

在仓库根目录运行 `pnpm dev`（macOS 和 Windows 命令相同），然后按终端打印的前端地址在浏览器里打开，默认是 `http://localhost:5173`。

开发模式下，前端由 **Vite**（前端的开发服务器和构建工具）提供。浏览器实际运行的是编译后的代码，但 Vite 会同时提供 **source map**（源码映射：记录编译后的代码对应源码的哪一行），所以在开发者工具里看到和打断点的，都是你写的 `.vue` 和 `.ts` 原文件。

### 打开开发者工具

推荐用 Edge 或 Chrome，两者的开发者工具是一样的。

| 系统 | 快捷键 |
| --- | --- |
| Windows | `F12` 或 `Ctrl + Shift + I` |
| macOS | `Cmd + Option + I` |

也可以在页面上点右键，选**检查**。

### 在 Sources 面板里打断点

1. 切换到 **Sources**（源代码）面板；
2. 按 `Ctrl + P`（macOS 是 `Cmd + P`），输入文件名，比如 `position`，从列表里选中要看的文件；
3. 点击代码左边的**行号**，行号上出现一个蓝色标记，断点就打好了。再点一次是取消；
4. 在页面上做一次会执行到这一行的操作，比如点**搜索**按钮。程序停下来，这一行被高亮。

程序暂停后，右侧可以看到：

- **Scope**（作用域）：当前能访问到的所有变量和它们的值；
- **Watch**（监视）：点 `+` 输入一个变量名或表达式，比如 `form.name`，它的值会一直显示在这里；
- **Call Stack**（调用栈）：程序是经过哪些函数一层层调用到这里的。

把鼠标停在代码里的变量上，也能直接看到它的值。

用面板上方的按钮（或快捷键）控制执行：

| 按钮 | 快捷键 | 作用 |
| --- | --- | --- |
| 继续 | `F8` | 一直运行到下一个断点 |
| 单步跳过 | `F10` | 执行当前这一行，停在下一行；遇到函数调用不进去 |
| 单步进入 | `F11` | 遇到函数调用时，进到函数里面 |
| 单步跳出 | `Shift + F11` | 执行完当前函数，回到调用它的地方 |

### 用代码打断点：`debugger`

在代码里写一行 `debugger`，开发者工具打开时，程序运行到这里就会暂停，效果和点行号一样：

```ts
function onSubmit() {
  debugger // 运行到这里暂停
  // …
}
```

找不到文件、或者代码在很深的地方时，这样更方便。

::: warning 用完一定要删掉
`debugger` 只用于本地调试，不能提交。电脑端的代码检查会把它当成错误：`pnpm lint`（`pnpm verify` 的第一项）会报 `no-debugger`，检查不通过。
:::

### 在 Network 面板里看请求

**Network**（网络）面板列出页面发出的所有请求。点一个请求，可以看到：

- **Headers**（请求头和响应头）：请求地址、方法、状态码，以及响应头里的 `X-Request-Id`；
- **Payload**（请求参数）：前端发出去的数据；
- **Response**（响应内容）：后端返回的数据。

本项目的接口都用统一的格式返回：

```json
{ "code": 0, "msg": "ok", "data": { "…": "…" } }
```

`code` 是 `0` 表示成功，数据在 `data` 里。出错时返回的是错误码、翻译好的错误信息和请求编号：

```json
{ "code": "…", "msg": "…", "traceId": "6f1c…" }
```

**traceId**（请求编号）就是每个请求的编号，和响应头 `X-Request-Id` 的值相同。前端的问题查到最后发现是后端返回了错误时，把 traceId 复制下来，到服务端日志里搜索，方法见[排查问题](/backend/debugging#先看-traceid)。

::: tip 先分清是前端还是后端的问题
在 Network 面板里看一眼响应：后端返回的数据是对的、页面显示错了，是前端的问题，在前端打断点；后端返回的就是错的，再去查后端。
:::

### Console 面板

**Console**（控制台）面板显示前端的报错和 `console.log` 的输出。页面不正常时先看这里有没有红色的报错，点报错右边的文件名可以跳到出错的那一行。

程序停在断点上时，也可以在 Console 里直接输入变量名或表达式，看它的值。

### Vue DevTools

**Vue DevTools** 是 Vue 官方的浏览器扩展，在 Chrome 应用商店或 Edge 加载项商店里搜索 **Vue.js devtools** 安装。安装后，开发者工具里会多出一个 **Vue** 面板，可以看到：

- **组件树**：页面由哪些组件组成，每个组件的 props 和状态；
- **Pinia**：本项目用 Pinia 管理全局状态（比如 `auth` 存当前登录用户和权限），可以直接看到每个 store 里的数据；
- **路由**：当前路由和所有已注册的路由。

Vue DevTools 只在 `pnpm dev` 的开发模式下可用，构建后的正式版本看不到。

也可以在 VS Code 里连接浏览器调试前端，不是必需的，本页不展开。

## 手机端

移动端有三种运行方式，调试工具各不相同。怎么启动它们，见[移动端开发](/core/mobile#安装与运行)。

| 平台 | 在哪里调试 |
| --- | --- |
| H5 | 浏览器开发者工具，和上面电脑端的方法完全一样。点开发者工具左上角的**设备工具栏**图标（`Ctrl + Shift + M`，macOS 是 `Cmd + Shift + M`），把页面切换成手机尺寸 |
| 微信小程序 | 运行 `pnpm -C mobile dev:mp-weixin`，在**微信开发者工具**里导入 `mobile/dist/dev/mp-weixin`。它自带调试器，也有 Console、Sources、Network 面板，用法和浏览器差不多 |
| App | 运行 `pnpm -C mobile dev:app`，在 **HBuilderX** 里导入 `mobile/dist/dev/app`，运行到手机或模拟器。App 打印的日志和报错显示在 HBuilderX 下方的控制台里 |

日常写页面优先用 H5 调试，最方便；小程序和 App 用来核对只在那个平台上才有的问题。

## 后端

后端的断点调试（用 VS Code 或 WebStorm 连接到 NestJS 服务端打断点）会在这一页以后的更新里介绍。在那之前，后端的问题请用 traceId 加日志、用 Swagger 直接调接口来排查，方法见[排查问题](/backend/debugging)。
